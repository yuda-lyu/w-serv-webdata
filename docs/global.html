checkFind(find, optopt) → {Object}

Description:

  • 檢核資料通道前端所送之find(表操作select、delAll之查詢條件)是否在白名單內

    前端所送之find來自不可信之客戶端，資料通道於呼叫authorizeExec與operOrm之前以此函數檢核。白名單為固定集合(最小集)：find為未給(undefined)或一般物件，各鍵為識別字(不為$開頭、不含點號、不為Object.prototype之成員名、不為'prototype'與'length'，長度不超過128，至多64個鍵)，各值為純量(字串不超過1024字元且不含NUL、有限數字、布林，不含null)或恰含單鍵$in之物件(值為純量之陣列)，且整個find之$in元素總數(跨鍵合計)至多1000個。非條件物件(null、陣列、字串、數字、布林、二進位等)、運算子($or、$where、$regex等)、巢狀物件等一律拒絕，不靜默忽略。

    通過者回傳全新且凍結之複本(只含已驗證之鍵與值，頂層值與$in之元素各只讀取一次)，之後授權與ORM收到者即此複本。通過不代表後端安全：字串值之語意(例如大小寫、數字字串、陣列欄位之包含)由各ORM後端決定。kpFunExt收到之參數未經此檢核，其作者可引用本函數自行把關(例如import checkFind from 'w-serv-webdata/src/checkFind.mjs')。

Source:
  • checkFind.mjs, line 64
Example
import checkFind from 'w-serv-webdata/src/checkFind.mjs'

let r = checkFind({ id: { $in: ['a1', 'a2'] }, name: 'alpha' })
console.log(r)
// => { ok: true, find: { id: { $in: ['a1', 'a2'] }, name: 'alpha' } } (凍結複本)

r = checkFind({ $or: [{ name: 'alpha' }] })
console.log(r)
// => { ok: false, reason: 'badKey' }

r = checkFind({})
console.log(r)
// => { ok: true, find: {} }

r = checkFind({}, { requireKey: true })
console.log(r)
// => { ok: false, reason: 'emptyFind' }

genPollingGate(opt) → {Object}

Description:

  • 產生輪詢([sys:polling])之身分關卡, 供注入w-serv-broadcast(1.1.11起)之opt.verifyPolling, 使輪詢與其他函數一樣先驗證身分

    輪詢之輸入為{ clientId, sysToken }(前端opt.getToken之值放於固定鍵__sysToken__), 不是資料通道之{ sysInputArgs, sysToken }, 由w-serv-broadcast於資料通道之前處理, 故身分關卡不在資料通道(Exec)的execFun內, 而經鉤子注入; execFun對[sys:polling]只略過(不回應), 見Exec

    關卡依序: ①帶token鍵者以getUserIdByToken(token)反查userId(即驗證身分之步驟), 每輪恰1次, 拋錯或reject一律拒絕(含公開者); 未帶token鍵者(已發布之舊前端元件)未出示token, 以空身分處理而不反查; ②userId為空字串者, 須[sys:polling]列於sysFuncsPublic(預設即列入)方放行; ③clientId須歸屬該身分: 首次放行時綁定clientId與userId, 其後以不同userId輪詢同一clientId即拒(clientId由前端自訂, 否則知道他人clientId者可取走其廣播) 「歸屬」之保證為綁定存活期間內userId一致, 先到先綁: 並非證明初次輪詢者原本擁有該clientId(連線識別由伺服端產生並綁定已驗證身分者才有此保證, 本套件沿用前端自訂clientId之既有協定)

    綁定之生命週期: 首次放行時建立; 該clientId逾時離線(w-serv-broadcast在線逾時固定10秒, 期間無任何一次被放行之輪詢, 發出clientLeave)時解除(release), 此後可由不同身分重新綁定; 伺服端clearBroadcast時全部解除(stop)並不再綁定; 被拒絕之輪詢不建立、不刷新綁定(亦不刷新在線身分), 故身分改變(例如登出再以他人登入而前端clientId未變)者須待舊綁定逾時, 期間輪詢被拒絕
